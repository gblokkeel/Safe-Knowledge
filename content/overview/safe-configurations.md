# SAFe Configurations

## Overview

SAFe offers **four configurations** to accommodate the needs of organizations of different sizes and complexity. Each configuration builds on the previous one, adding more structure for larger and more complex enterprises.

The four configurations are:
1. **Essential SAFe** — The minimum viable configuration
2. **Large Solution SAFe** — For large, complex systems
3. **Portfolio SAFe** — Adds strategy and governance
4. **Full SAFe** — The complete enterprise configuration

## Essential SAFe

### Description
Essential SAFe is the most foundational configuration and the recommended starting point for most organizations. It includes the Team and Program Levels — the minimal set of roles, events, and artifacts needed to scale Agile.

### When to Use
- Organizations new to SAFe
- Smaller enterprises or business units
- Organizations wanting to start simply and expand

### Key Elements
- **Agile Teams** using Scrum or Kanban
- **Agile Release Train (ART)** — 50–125 people aligned to a common mission
- **Program Increment (PI)** — 8–12 week delivery cycle
- **PI Planning** — The ART-wide quarterly planning event
- **System Demo** — Regular demonstrations of integrated work
- **Inspect & Adapt** — Quarterly retrospective and improvement planning

### Roles
- Scrum Master / Team Coach
- Product Owner
- Agile Team Members
- Release Train Engineer (RTE)
- Product Manager
- System Architect / Engineer
- Business Owners

### Key Events
- Sprint Planning, Daily Stand-up, Sprint Review, Sprint Retrospective
- PI Planning, System Demo, Inspect & Adapt, ART Sync, Innovation & Planning Iteration

## Large Solution SAFe

### Description
Large Solution SAFe adds the **Large Solution Level** for organizations that build large, complex systems that require multiple ARTs and Suppliers. It includes the Solution Train — a coordination mechanism above the ART level.

### When to Use
- Systems too large or complex for a single ART
- Defense, aerospace, or large enterprise systems
- Products requiring coordination across many teams and suppliers
- When government or regulatory compliance adds complexity

### What It Adds to Essential SAFe
- **Solution Train** — Coordinates multiple ARTs toward a common solution
- **Solution Train Engineer (STE)** — Leads the Solution Train
- **Solution Manager** — Product management for the large solution
- **Solution Architect/Engineer** — Technical leadership across the solution
- **Pre-PI Planning** — Aligns ARTs before PI Planning
- **Post-PI Planning** — Consolidates plans after PI Planning
- **Solution Demo** — Demonstrates integrated system capabilities
- **Solution Intent** — Repository of requirements and design decisions
- **Solution Backlog** — Manages Capabilities for the large solution
- **Capabilities** — Large features that span multiple ARTs

### Key Events (additional to Essential)
- Pre-PI Planning
- Post-PI Planning
- Solution Demo

---

## Portfolio SAFe

### Description
Portfolio SAFe adds the **Portfolio Level**, connecting business strategy to execution through Lean Portfolio Management (LPM). It governs the investment in value streams and ensures strategic alignment.

### When to Use
- Organizations that need to govern multiple ARTs or value streams
- Enterprises with complex investment decisions
- When linking business strategy to program execution
- Organizations managing large capital allocation decisions

### What It Adds to Essential SAFe
- **Lean Portfolio Management (LPM)** — The function that aligns execution to strategy
- **Strategic Themes** — Business objectives that connect the portfolio to enterprise strategy
- **Portfolio Vision** — Long-term view of the portfolio's intended direction
- **Value Streams** — How the organization creates and delivers value
- **Portfolio Canvas** — Summarizes the portfolio's mission, value streams, and budget
- **Portfolio Backlog** — Manages Epics for the portfolio
- **Portfolio Kanban** — Manages the flow of Epics through analysis and implementation
- **Participatory Budgeting (PB)** — Collaborative approach to budget allocation
- **Portfolio Roadmap** — Communicates planned delivery over time
- **Epic Owners** — Stewards of Epic implementation
- **Enterprise Architects** — Guide the technical direction of the portfolio

### Key Roles (additional)
- LPM Team (executives, business managers, enterprise architects)
- Epic Owner
- Enterprise Architect

### Key Artifacts (additional)
- Strategic Themes
- Portfolio Vision
- Portfolio Canvas
- Portfolio Backlog
- Portfolio Roadmap

## Full SAFe

### Description
Full SAFe is the most comprehensive configuration, combining all three other configurations: Essential, Large Solution, and Portfolio SAFe. It is designed for the largest enterprises building the most complex systems.

### When to Use
- Very large enterprises with hundreds of teams
- Organizations building complex, integrated systems (e.g., defense systems, large financial platforms)
- When all levels — Team, Program, Large Solution, and Portfolio — are needed

### What It Includes
Full SAFe is the union of all elements from:
- Essential SAFe (Team + Program levels)
- Large Solution SAFe (adds Large Solution level)
- Portfolio SAFe (adds Portfolio level)

### Organizational Scale
| Configuration | Approx. Team Members |
|--------------|---------------------|
| Essential SAFe | 50–125 per ART |
| Large Solution | Multiple ARTs (hundreds) |
| Portfolio SAFe | Multiple ARTs |
| Full SAFe | 500–5000+ across all levels |

## Choosing the Right Configuration

Use this decision guide to select the right starting configuration:

```
Start with Essential SAFe
       ↓
Do you build very large/complex systems requiring multiple ARTs?
  YES → Add Large Solution Level
       ↓
Do you need to align multiple value streams to business strategy?
  YES → Add Portfolio Level
       ↓
Both Large Solution AND Portfolio needed?
  YES → Full SAFe
```

### General Guidance
- **Start simple** — Most organizations begin with Essential SAFe
- **Evolve gradually** — Add levels as the organization matures
- **Don't over-engineer** — Only add complexity you genuinely need
- **Customize** — SAFe is a framework, not a prescription; adapt to your context
